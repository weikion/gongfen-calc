# 任务工分计算器（gongfen-calc）

> 丢进来一张格式再乱的任务清单，还你一份逐任务打好评级的 Excel 打分表——字段自动识别、单位自动归一、每个分数可回溯到原表行号；数据不足时如实降级，不编造分数。

![Python](https://img.shields.io/badge/python-3.9%2B-blue)
![License](https://img.shields.io/badge/license-MIT-green)
![Version](https://img.shields.io/badge/version-2.1.0-orange)

一个给**任务**打分的脚本工具（点因子法任务版）。读 Excel / CSV 任务清单 → 自动认字段 → 归一单位 → 质检 → 批次评级 → 多维度打分 → 输出带格式的 Excel 结果表。

全程脚本执行：**没有模型"看着差不多"的判断，也没有中途弹窗问你**。每个分数都能回溯到原表行号和命中依据。

---

## 为什么需要它

- **任务表格式从来不统一**：表头在第 3 行、纵向合并单元格、`2人天 / 8h / 约3天 / 待定` 混排、合计行藏在数据中间、一张表里重复出现好几个区块表头……
- **手工拍分不可复核**：谁也说不清某个任务为什么是 80 分而不是 60 分，争议一旦起来就收不住。
- **维度不全时不敢分钱**：只有任务名、没有工时和优先级，硬算出来的分数本质上是"猜的"。

处理原则只有一条：**能算的算清楚，算不了的如实说算不了**——绝不静默补一个看起来合理的数。

## 30 秒上手

```bash
# 1. 装依赖（Windows 直连 pypi 容易超时，建议走阿里云镜像）
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com

# 2. 跑（一条命令出结果，全程不询问、不中断）
python scripts/run.py 任务清单.xlsx

# 没有现成的表？先跑仓库自带的样例
python scripts/run.py tests/fixture_dirty.xlsx --out-dir out
```

跑完在输出目录得到 4 个文件：

| 文件 | 用途 |
|---|---|
| `任务清单.gongfen.xlsx` | **主交付物**：打好评级的 Excel 结果表（4 个 sheet） |
| `任务清单.gongfen.md` | Markdown 报告，适合贴聊天 / 贴文档 |
| `任务清单.gongfen.json` | 中间结构，复核与下游集成用 |
| `baseline.json` | 首次运行自动存档，第二次起启用环比检测 |

## 输出：Excel 结果表

| sheet | 内容 |
|---|---|
| **工分明细** | 原表行号 / 任务ID / 任务名 / 各维度档位（表头带归一化权重）+ 原始值 / 完整度 / 分层 / 层内排名 / 小计 S / K 系数 / 工分 P / 判定依据 |
| **批次汇总** | 分支结论、总分 T、总工分、分层分布、维度权重与覆盖度、口径冻结、补齐字段建议 |
| **质检与自检** | 质检提示、自检结果、被打折任务、**被剔除行（行号 + 原因 + 原文）**、冻结任务、红线声明 |
| **字段识别** | 列号 / 原始列名 / 识别为 / 置信度 / 识别方式 / 样例值 + 未映射列 + 仲裁日志 |

几个设计上的细节：

- 明细里带**原表行号**，任何一个分数都能回到原表定位，也方便你自己 VLOOKUP 合成"原表 + 打分列"。
- **容器父任务也会列出来**（标"不计分（防父子重复计分）"），否则你会以为脚本漏了任务。
- 被剔除的行不是静默丢掉，全部列在「质检与自检」里，附行号、原因和原文。

## 评分口径

### 公式

```
单任务小计   S = Σ(档位_i × 权重_i) / Σ(有效维度权重_i)      # 缺失维度从分子分母同时剔除，不填 0、不填中位 3
单任务工分   P = S × 20 × K_偏离 × K_体量 × K_角色 × K_子任务   # 所有 K 只乘工分，不进小计 S
批次总分     T = Σ S（只对 L1 + L2 求和）
```

- `K_偏离`：工时超出批次 P90 的部分按 30% 计入，防"报得越多分越高"；n < 10 不打折。
- `K_子任务`：父任务被判为独立任务时，子任务 ×0.6，防父子重复计分。
- `K_体量` 默认关闭，`K_角色` 默认 1.0。

### 维度与权重

| 维度 | 基础权重 | 启用条件 |
|---|---|---|
| A 困难程度 | 20 | **只要有任务名/描述就启用**，走关键词规则表（命中率低只提示，不关闭） |
| B 工时投入 | 20 | 识别出工时/耗时/人天/工期，或起止日期 |
| C 经济效益 | 20 | 有金额列且"非空且非 0"覆盖率 ≥ 50% |
| D 风险责任 | 15 | 有影响范围/SLA/不可逆等专列（优先级不算） |
| E 质量结果 | 15 | 有验收结论/返工次数/客户评价等专列 |
| G 紧迫性 | 10 | 有截止日期或优先级 |
| H 协同成本 | 5 | 有协作方/参与人列 |
| J 复用价值 | 5 | 有交付物列且三档枚举有命中 |
| F 技能门槛 / I 创新度 / K 战略对齐 | — | **永久关闭**（技能门槛会让同一任务换人做就变分，属系统性偏差） |

缺失维度不惩罚：权重按已启用维度重新归一化，而不是给缺失项填 0。

### 分层与总分

完整度 = 该任务有效维度权重和 ÷ 本批启用维度权重和（不是固定 100）。

| 层 | 完整度 | 是否进总分 |
|---|---|---|
| L1 | ≥ 90% | ✅ |
| L2 | 60% – 90% | ✅ |
| L3 | < 60% | ❌（数据不足，单独列出，另出一行含 L3 的参考总分） |

排名只在层内做，**跨层名次不可直接比较**。

## 数据不足时会怎样：五个分支

分支是结论的一部分，不是报错。

| 分支 | 触发 | 结果能用于什么 |
|---|---|---|
| `A_正常` | 启用维度权重 ≥ 60%，有效自由度 ≥ 3 | 可排名，作分配**参考** |
| `B_可排名` | 权重 45–60%，或单维权重过高，或无日期锚点 | 可排名，**不建议直接分配** |
| `D_体系退化` | 有效自由度 < 3，或有效维度 ≤ 2 | **仅排序参考**，禁作分配依据 |
| `C_仅描述` | 权重 < 45%，或任务数 < 3 | **仅描述统计**，不输出工分 |
| `E_失败` | 连任务名/描述都认不出、表头定位失败、文件加密 | 不出分，回显失败三件套 |

C / D 分支下：Markdown 里工分列渲染为「—」，Excel 里「工分 P」列留空，另给一列明标 **「参考工分（仅供排序对照·不可用于分配）」**。

如果你确认这批数据就是要用，显式加一个参数即可（脚本不会替你做这个决定，并会在报告里追加警示）：

```bash
python scripts/run.py 任务清单.xlsx --force-points
```

## 边界：这个工具不做什么

1. **不产出"某人应得 X 分 / 应评为 X 级"**。输出的是**任务分**，不是个人绩效等级。
2. **不产出淘汰 / 扣罚名单**，也不设计这类规则。
3. **不静默改分**。工时与日期矛盾、疑似拆分、分布偏斜——全部只提示并列清单，判断权归人工。
4. **数据不足不伪装成可用**。宁可降级，也不给一个看似能分的数。
5. **估算值不冒充实测值**。关键词推断出的难度一律标 `estimated`，并在总分旁标注。

## 命令行参数

| 参数 | 说明 |
|---|---|
| `--out-dir DIR` | 输出目录（默认与输入同目录） |
| `--xlsx / --json / --md PATH` | 分别指定三种产物的路径 |
| `--override 列号=字段名` | 脚本认错列时人工强制指定，**唯一的人工介入点**，可多次；列号从 1 开始（查 Excel「字段识别」sheet） |
| `--force-points` | 明知覆盖度不足也要出工分（默认不给） |
| `--baseline PATH` | 指定 baseline.json 做环比（默认自动存档、二次运行生效） |

示例：

```bash
python scripts/run.py 任务清单.xlsx --override 3=hours --override 5=money
```

## 定制

所有经验参数集中在 `scripts/params.py`，改完重跑即可，**不要手工改分数或改 JSON**：

- `WEIGHTS` —— 各维度基础权重
- `A_KEYWORD_TABLE` —— 难度关键词→档位映射表（4/3/2/1 档）。不同业务词表差异很大，建议拿自己的任务表校准一遍
- `HOURS_PER_MANDAY`、`WORKDAY_FACTOR`、`HOURS_DEVIATION_FACTOR` —— 工时口径
- `ABSOLUTE_BANDS`、`COLLAB_LEVEL_CUTS` —— 分档切点

完整口径说明见 `references/scoring_anchors.md`（唯一口径来源）与 `references/field_dictionary.md`（别名词典、解析正则、质检清单）。

## 已知限制

- `.xls` 旧格式与加密文件未支持（需 xlrd / msoffcrypto）
- 多 Sheet 歧义（评分分差 < 1.5）需人工指定，默认不合并
- 金额「万元」单位行暂未回填换算（同列同尺度，不影响相对档位）
- Excel 输出**不回写你的原文件**，只另存 `*.gongfen.xlsx`
