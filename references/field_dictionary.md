## 0. 一句话原则

**能确定才采，不能确定就报"需确认"或"分析失败"。** 猜出来的数比没有数危害大得多——因为它看起来是对的。

### 1.1 置信度与阈值

```
conf = 别名权重 × 长度惩罚(0.95^(多余字数)，下限0.72) × 匹配级系数
     × 冲突系数(命中多维度 0.60) × 内容系数(一致 +15% / 矛盾 ×0.50)
```

| 区间 | 处置 |
|---|---|
| ≥ 0.85 | 自动采纳 |
| 0.60–0.85 | 采纳，列入「待确认映射」 |
| < 0.60 | 不采纳，进「未映射列」 |

**强制确认（无论多高）**：`money` / `skill` / `strategy` / `difficulty`。

### 1.2 一列命中多维度：仲裁

| 冲突 | 规则 |
|---|---|
| `等级 / Level` | 含 风险/安全/不可逆 → **risk**；否则 → **difficulty**（置信 ×0.7，转待确认） |
| `价值` | 数值且中位 ≥100 → **money**；枚举高/中/低 → **risk** 的重要性（不进金额） |
| `状态 / Status` | 枚举含 通过/驳回/返工/验收 → **quality**；枚举含 已完成/进行中/未开始 → **progress，不参与打分** |
| `类型 / 标签` | 枚举含 探索/预研/试点 → **innovation**；否则 → **difficulty**（任务类型映射） |

**"状态"是关键**：国内工分表里 85% 的"状态"是进度，不携带质量信息。当质量用，会让所有已完成任务质量分相同，E 维退化为常数。

### 1.3 列名全不命中时：内容特征反推（置信度上限 0.65，必然人工确认）

| 特征 | 反推 |
|---|---|
| 唯一率 >0.95 且均长 5–60 且中文占比 >0.3 | task_name |
| 枚举 ⊆ 等级词 | difficulty |
| 枚举 ⊆ 进度词 | progress（不用） |
| 数值率 >0.9 且中位 ≥1000 且最大 ≥1e4 | money |
| 数值率 >0.9 且 1≤中位≤40 且最大 ≤300 | hours |
| 可解析日期率 >0.85 | date（多列按列序：前 start 后 end） |

## 2. 单位换算

### 2.1 工时 → 小时

| 单位 | 系数 | 是否需校准 |
|---|---|---|
| 小时 / h / hr / 时 | ×1 | 否 |
| 人天 / 人日 / 工作日 / 天 / 日 / d / md | ×8 | **是**（研发有效工时常见 6.5–7） |
| 周 / w | ×40 | **是**（是否含周末） |
| 月 / m | ×160 | **是**（20 工作日；HR 口径 21.75 天≈174h） |
| 分钟 / min | ÷60 | 否 |
| 起止日期推算 | 自然日 ×8×0.7 | **是**（不扣节假日 → 高估 10–12%） |

**单位判定优先级（不可颠倒）**：

1. **列名 / 单元格数字格式**（最可靠，制表人显式声明）
2. **日期锚点反算**：取同时有起止日的任务，`可用 = 自然日×8×0.7`；`值/可用≈1` → 小时，`值×8/可用≈1` → 人天
3. **数量级推断**：`中位≤3 且最大≤40` → 人天；`中位≥8 且最大≥80` → 小时；其余 → 不确定，**必须问用户**

> 猜错是 8 倍误差、且方向一致（全表同向偏大或偏小），排序看起来仍"合理"——最阴险的一类错。

### 2.2 金额 → 元

| 单位 | 系数 |
|---|---|
| 元 / ¥ / ￥ / RMB | ×1 |
| 千 / k / K | ×1e3 |
| 万 / w / W / 万元 | ×1e4 |
| 百万 / m / M | ×1e6 |
| 亿 | ×1e8 |
| $ € £ | **不换算**，要求用户统一币种 |

**列名已含单位不再叠加**：列名 `金额(万元)` 里填 `1.2万` → 报警告，不乘两次。

### 2.3 日期

| 形态 | 处理 |
|---|---|
| Excel 序列号 40000–60000 | 按 1899-12-30 起算；**超出区间不按日期解析** |
| `2026/1/1` `2026-1-1` `2026.1.1` `2026年1月1日` `20260101` | 正则解析 |
| `1/1/2026` 歧义 | 第二位 >12 → D/M/Y；否则列内多数投票；仍不决 → 需确认 |
| 区间 `2026/1/1-2026/1/5` | 拆 start/end |
| 工期 | `end − start + 1`（含首尾） |
| 自然日 → 工时 | `×8×0.7` |

## 3. 值解析规则

### 3.1 工时单元格

```
^[约大约≈~<>≥≤\s]*([\d,]+(?:\.\d+)?)\s*(?:[-~至到]\s*([\d,]+(?:\.\d+)?)\s*)?
 (小时|人天|人日|工作日|分钟|hrs|hr|min|天|日|周|月|h|d|w|m)?\s*[左右]?$
```

- `约3天` / `3-5天` → 取中位或单值，标 `estimated=True`
- `待定` / `TBD` → NaN，进"未解析清单"，**不填 0**
- 小数（0.5 天）**保留，不 round**（round 会抹掉长尾小任务）

### 3.2 金额单元格

```
^[¥￥$€£]?\s*([\d,]+(?:\.\d+)?)\s*(亿|百万|万|千|[kKwWmM])?\s*元?\s*$
```

先删千分位逗号与空格，再匹配。

### 3.3 等级单元格

| 输入 | 输出 |
|---|---|
| 数字 1–5 | 原值 |
| 数字 1–10 | `round(x/2)`，标 estimated |
| 数字 1–100 | `round(x/20)`，标 estimated |
| 极高/很高/非常难/复杂 | 5 |
| 高/困难/较难/较高/难 | 4 |
| 中/一般/普通/中等 | 3 |
| 低/较低/简单/容易 | 2 |
| 很低/极低/极简 | 1 |
| `P0` | 5（仅用于紧迫性） |
| `P1` | 4 ｜ `P2` 3 ｜ `P3` 2 |

### 3.4 空值集（唯一入口）

```
""  "-"  "--"  "—"  "——"  "/"  "\"  "无"  "暂无"  "空"  "未知"
"n/a" "na" "null" "none" "nan" "待定" "待补充" "tbd" "?" "？"
```

### 3.5 协作方计数

按 `、 , ; ； / 换行` 分割后计数；纯数字直接用。

## 5. 结构类脏数据

| 现象 | 判定 | 处置 | 依据 |
|---|---|---|---|
| 表头不在第 1 行 | 前 15 行打分：`3×别名命中率 + 2×填充率 + 1.5×短文本比 + 2×下一行像数据 − 3×合计/说明词(仅当命中≤1) − 2.5×单格标题 − 2.5×本行含数值` | 取最高分（阈值 0.45） | 单格大标题、编制人行不是表头 |
| 双层表头 | 本行填充率<0.6 且下一行 ≥0.8 且命中不减 | 拼 `父|子`，数据区下移 | 合并单元格让父层重复占位 |
| 单位行 | 整行匹配 `单位：X` 或 `(X)` | 抽出单位提示，数据区下移 | 当数据行会造出假任务 |
| 纵向合并任务名 | 合并跨度 >1 行 | **按锚点聚合成 1 条**，工时/金额求和 | 直接向下填值会让总工时成倍放大 |
| 合计行 | 关键词 `合计/小计/总计/累计/汇总/总额/平均/均值/total/sum/avg` | 剔除 | 污染任务数、分位数边界、总分 |
| 无关键词的伪合计 | **可加性自检**：本行 ≈ 上方连续 ≥2 行之和（误差 1%） | 首列为空 → 剔除；首列有正常任务名 → **只标记不剔除** | 有些表不打"合计"二字 |
| 重复表头 | 与表头行相似度 ≥0.8 | 剔除 | 分页打印常见 |
| 备注/分隔/空行 | `备注/注：/说明/制表/审核` 或全空或全符号 | 剔除 | 会变成假任务 |
| 多 Sheet | 评分：`4×有任务名列 + 3×别名命中 + 2×数据量 + 3×有筛选器 − 5×说明页` | 分差 <1.5 → 报歧义 | 多 sheet 常是不同月份，合并会重复计入 |

## 6. 工时防护（防虚报，但不误伤）

| 机制 | 规则 |
|---|---|
| 偏离度打折 | `h_eff = min(h,P90) + 0.3×max(0,h−P90)`，n≥10 启用；**作用于权重 K=h_eff/h，不改变 1–5 档位** |
| 物理可行豁免 | 有起止日期且 `h ≤ 可用工期` → `K=1`，标「已核验：物理可行，未打折」 |
| 日期矛盾 | `h > 可用工期×1.5` → **仅标记 + 单列复核，不自动改分** |
| 低效率标记 | E 可用时：工时高档 + 质量 1–2 档 → 标「低效率，建议复核」 |
| 无对冲提示 | E 未启用且 B 权重 >35% → 报告首屏强制提示「存在虚报激励，无对冲维度」 |

> **为什么不做无条件截断**：把 >P90 压平等于对全批最大 10% 任务默认有罪。真实三个月迁移被削，比虚报更难解释。

## 7. 失败回显（三件套，缺一即实现缺陷）

任何"分析失败"都必须给出：

1. **①已识别到的列名清单**（列名 → 识别为 → 置信度 → 方法）；一个都没识别到时，给出各 Sheet 的**列号 + 样例值**
2. **②缺失的必要字段**
3. **③建议补充的列**

禁止笼统报错（如"文件格式不支持"）。用户拿到报告后应能自己判断：是改表，还是手动指定映射。
